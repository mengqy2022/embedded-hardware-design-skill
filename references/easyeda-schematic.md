# 嘉立创EDA原理图自动化：器件、引脚与网络

用于嘉立创EDA专业版实时原理图自动化，配合 [SCH-01～34](schematic-style.md) 和 [检查清单](../assets/SCHEMATIC_REVIEW.md)。来源为 [S14](sources.md) 的固定上游提交及本机 easyeda-api 1.1.56 文档。这里只做资料核对，尚未在当前 EDA 版本运行这些方法。

## 工作顺序

1. **确认工程和工具。** 需要实时修改时读取已安装 `easyeda-api` Skill 的当前说明与对应 API 类；核对 Bridge 服务身份、目标窗口、原理图页和修改范围。端口按当前服务发现，不硬编码 49620，不因安装本规则自动启动或改写任何工程。没有工具时继续资料审查，保留未验证状态。
2. **读取已有对象。** 获取真实器件、引脚、导线、网络对象及页面分框，保存修改前网表和必要原生回退点。优先沿用现有器件及用户布局；只对新增器件查料。
3. **查料并消歧。** 批量使用 `lib_Device.getByLcscIds`，允许多匹配时逐项核对准确型号、封装和库 UUID，不取首项即认定匹配。属性字段使用当前 API 支持的准确键名；不能把显示语言当作字段名称。
4. **先确定空间与引脚。** 功能框容纳符号、引脚、短线和文字，透明填充避免遮挡；用真实包围盒和网格安排位置，不能将 ESP32 示例固定间距推广到全部符号。器件移动/旋转后重新调用 `sch_PrimitiveComponent.getAllPinsByPrimitiveId`，不按外观或旧坐标猜端点。
5. **建立明确映射。** 记录器件位号、物理脚号、用途、电压域、目标网络及证据。核对 NC、隐藏电源、EP/屏蔽壳/机械脚、器件内部相连脚和连接器观察方向；未知脚单列，不能自动略过。四脚按键按准确型号的内部触点图核对，不能统一假定某一脚号配对。
6. **按需连线及标注。** 关键局部拓扑直接可见，远处或跨页片段使用必要标签。电源/地按实际网络采用 `createNetFlag`，信号按用途和作用域采用 `createNetPort` 或工具支持的网络标签；`IN/OUT/BI` 反映实际接口方向，不能把所有信号强制设为 BI。SCH-25 的连续同网单标签继续优先；不把“每引脚一个标签”作为完工标准。
7. **限制变更并读回。** 对受影响对象执行适量批次，保存创建 ID 和逐项结果；使用临时 UTF-8 JSON 文件或结构化 HTTP 请求传参，避免 shell 插值。批次超时先读回已完成对象，再补缺失项，防止重试复制器件/标签。实时 API 调用按当前签名正确 await。
8. **完成适用检查。** 从实际引脚追踪导线端点和目标网络，比较修改前后/预期网表，检查未连接与多页标签作用域，查看整页与密集局部，执行当前版本原理图检查。器件数、标签数和导线数只证明对象数量，不证明电路闭合或正确。

## 版本相关的 API 注意事项

| 主题 | 核对方法与适用边界 |
|---|---|
| 单位、坐标和旋转 | 上游示例称原理图单位为 10 mil、Y 向上，但其引脚旋转/偏移和矩形说明不完全一致。先用当前文档、已有对象及必要的可回退小样验证单位、Y 方向、旋转和矩形锚点；不能复制上游表格直接批量落图 |
| 文本对齐枚举 | 上游报告部分 Bridge 未注入 `ESCH_PrimitiveTextAlignMode`；本机文档有该枚举定义（如 CENTER_TOP=4）。先检查运行上下文；只有确实缺失时才用当前文档确认的数值并注明枚举含义，不全局禁用枚举 |
| 器件位号与异步对象 | 按当前对象支持的 `toAsync()`、`setState_Designator()`、`done()` 或相应修改接口写入，检查返回值并重新读取位号；不假定所有创建调用都成功或所有版本对象形态相同 |
| 导线几何和网络 | 优先按当前类文档使用 `getState_Line()` / `getState_Net()`；上游报告的 `.line` / `.net` 仅适用于实际返回的原始对象，不调用不存在的 `getState_Coordinates()`。保留多折点/嵌套坐标结构，不能一律只取四个数。跨页网络名可能异步刷新，不能将即时字段当作最终网表证据 |
| 器件数量 | 上游观察到网络旗标/端口也出现在组件集合，且通常没有位号。用类型/库身份/已保存 ID 和位号共同区分；缺位号的真实器件也是待检查对象，不能简单丢弃 |
| 透明框与尺寸 | 上游使用 `fillColor: "none"` 以及特定字号/边距；按当前 API 和导出图确认透明及可读，不把这些示例参数当成物理制造尺寸 |

## 修改和删除的边界

删除器件不保证自动清理它的短线、标签和端口。先建立受影响对象 ID 清单，结合原引脚端点、实际连接关系、网络及对象身份定位。共享主干、T 分支和邻居标签必须保护；坐标距离只能用于筛选候选，不能作为删除依据。

只删除确认由该器件局部扇出独占且本次需要替换的对象。移动后尽量更新现有对象；创建前检查是否已存在同样连接。读回清理结果及邻接分支，检查无孤立标签、悬空线、重复对象或意外并网。出现无法归属的对象时保留并记录，不能用区域全删重画覆盖用户手动整理。

## 对上游示例的取舍

- **采用：** 按功能分框、按实际引脚位置生成短连接、批量查料、结构化传参、修改后清理孤立对象、区分组件集合与真实器件。
- **调整：** 逐脚标签改为按需标签；固定 10 单位扇出及固定模块尺寸改为按当前符号/文字/网格确定；统一 BI 改为准确方向；空间范围删除改为连接关系和对象 ID 核实。
- **不继承：** 示例 ESP32/LCD/按键的脚号、供电方案、器件数、网络表和未经当前工程验证的坐标/性能结论；不要求用户切换 Plan 模式后才允许工作。

上游文件和示例已经单独安装供查阅；本整合文档为方法概括与纠偏，不再分发上游原文或示例工程。缺失或冲突的 API 行为须在未来实际任务中核验，不将本次阅读报告为现场验证通过。
